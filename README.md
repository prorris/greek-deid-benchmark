# Greek Clinical De-identification Benchmark (Morpheus benchmark corpus)

A benchmark for clinical-text de-identification in Greek: 500 fully synthetic
discharge notes (300 cardiac surgery, 100 cardiology, 100 nephrology) with a
dual-reviewed, arbitrated gold standard of 7,937 must-redact identifier
instances and 6,747 must-survive clinical probes, plus the complete scoring
rules, the evaluated system's outputs, and every scored decision.

**Everything in this repository is synthetic. No real patient data of any
kind was used at any stage.** Names, identifiers, addresses and clinical
narratives were generated by a large language model (Gemini 3.1 Pro, Google)
under the prompts in `generation/`; any resemblance to real persons is
coincidental.

The benchmark evaluates Morpheus, the de-identification engine of a locally
running clinical data-extraction application developed by the authors. The
engine itself is proprietary; its frozen version is identified by the
pipeline fingerprint `765328fbf1241ea4`, recorded in every result file. The
corpus, annotations, scoring rules, outputs and per-decision results
published here allow every reported number to be independently recomputed,
and allow any other de-identification system to be evaluated against the
same standard.

## Layout

- `corpus/` — the 500 notes.
  - `deid_corpus_gemini500.jsonl` — one JSON object per note: `id`, `text`,
    and `phi` (generation-time annotations: `expect: "redact"` values and
    `expect: "survive"` clinical probes). The must-redact entries are the
    PRE-annotation; the authoritative redaction gold standard is
    `annotations/gold_standard.json`.
  - per-specialty JSONL files (same content, split).
  - `corpus_pdfs_500.zip` — the notes rendered as realistic hospital-layout
    PDFs (four house styles), for document-processing use cases.
- `annotations/`
  - `gold_standard.json` — the arbitrated gold standard: per note,
    non-overlapping character spans (`start`, `end`, `category`, `fine`,
    `text`) over `text` in the corpus file. Built by
    `scoring/build_gold_standard.py`.
  - `review_A_page1-5.json`, `review_B_page1-5.json` — the two reviewers'
    full corrected annotation sets (500 notes each, blinded, independent).
  - `iaa_report.md`, `disagreements.json` — inter-annotator agreement
    (F1 = 0.998) and the 31 disagreements; `arbitration.json` — the senior
    author's ruling on each.
  - `must_survive.json` — the 6,747 must-survive clinical probes, collected
    per note from the corpus file (see "The must-survive probes" below).
- `scoring/`
  - `benchmark_score.py` — the complete scoring implementation: outcome
    definitions, the attributable-part rule, Wilson intervals, per-category /
    per-specialty breakdowns. Reads a results JSONL + the gold standard.
  - `benchmark_compare_runs.py` — the reproducibility comparison
    (decision-by-decision) between two runs.
  - `iaa_and_disagreements.py`, `build_gold_standard.py` — annotation-stage
    tooling.
  - `benchmark_run.py`, `benchmark_profile.py` — the harnesses that produced
    the result files. They call the proprietary engine and therefore cannot
    be executed from this repository alone; they are included to document
    exactly how the outputs were produced (the egress text is the output of
    the de-identification pass followed by the tokeniser pass; the egress
    guard is scanned on that same text).
- `results/`
  - `run1_results.jsonl`, `run2_results.jsonl` — the full outgoing
    (de-identified) text of every note in both independent benchmark runs,
    with the egress-guard flags and per-note wall-clock time. Surrogate
    values differ between runs by design (they are re-randomised on every
    run); scoring is by verbatim presence of original values.
  - `*_decisions.json` — every scored decision (7,937 identifiers + 6,747
    probes per run).
  - `*_summary.md` — the scored reports.

- `surrogates/`
  - `morpheus_1.0_surrogate_pools.json` — the pools of artificial replacement
    values the evaluated engine drew from (names, towns, street and hospital
    name parts). Values only; see `surrogates/README.md`.

## Reproducing the reported numbers

```
python3 scoring/benchmark_score.py results/run1_results.jsonl
python3 scoring/benchmark_compare_runs.py results/run1_results_decisions.json results/run2_results_decisions.json
```

(The scripts read the corpus, the annotations and the results from this
repository's own layout; no paths need to be changed. Python 3, standard
library only.)

## The must-survive probes

Most de-identification benchmarks score only what must be removed. This one
also scores what must be **kept**: 6,747 clinical probes — drug names (1,849),
diagnoses (993), laboratory values (953), Greek clinical section headers
(835), procedures (737), measurements (649), Greek clinical abbreviations
(554) and eponyms (177). A system that removes every identifier by also
removing «Marfan», «LIMA» or a drug name has destroyed the note; the probes
measure that.

- **Where they are.** In the corpus file, every `phi` entry with
  `expect: "survive"`. For convenience the same probes are collected in
  `annotations/must_survive.json` (`scoring/build_must_survive.py` rebuilds
  it; the corpus file remains the source).
- **What a probe is.** A category and a text value. Probes carry no character
  offsets: a probe is *kept* if its value still stands verbatim in the
  system's outgoing text, and *destroyed or altered* otherwise
  (`scoring/benchmark_score.py`). One probe of category `clinical_reference`
  is reported under `lab_value`.
- **How they were made.** Written with the notes at generation time and kept
  as accepted; the dual review and arbitration concerned the must-redact
  identifiers and did not modify the probes.
- **Scoring another system.** Produce one outgoing text per note, in the
  shape of `results/run1_results.jsonl`, and run `scoring/benchmark_score.py`
  on it: both sides — identifiers removed and probes kept — are reported.

## Realistic values and coincidental matches

The notes are written to look like real Greek hospital documents, so the
identifiers in them have real-world shapes. It is worth being exact about what
is real and what is not:

- **Real by design:** the hospitals, their public addresses, switchboard
  numbers, websites and e-mail addresses, and the towns and street names.
  These are public facts about institutions and places, not about people.
- **Invented:** every patient, relative and clinician name, every date of
  birth, social security number (ΑΜΚΑ), hospital record number, home address
  pairing, personal telephone number and personal e-mail address, and every
  clinical history. No value was taken from any real person or record.

Invented values were generated to be realistic, not checked against any
registry, and Greece has no number range reserved for fiction. A personal
telephone number, an ΑΜΚΑ, or a name-and-street combination in the corpus may
therefore coincide with one that exists. **Any such match is unintended and
carries no information: nothing in a note describes the holder of a matching
number, name or address.**

If a value in this corpus is yours and you would like it changed, open an
issue on this repository or write to the corresponding author of the
accompanying paper. It will be replaced in the next version of the dataset;
the Zenodo record keeps every version, with the change noted.
